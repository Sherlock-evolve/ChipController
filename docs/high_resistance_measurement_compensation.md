# 高阻段电阻测量偏小问题排查与补偿记录

记录日期：2026-07-07

## 背景

ChipController 通过 CN9 四线端子对外部芯片或标准电阻进行测量：

- `I+ / I-`：输出并采样总电流，电流由 R64 1 ohm 采样电阻换算。
- `V+ / V-`：接入 U14 AD7190 电压 ADC，测量负载两端电压。
- 固件原始电阻计算为 `R = |V_load| / |I_total|`。

前期 150 ohm 附近的测量已经通过固定零点和增益校准达到较好结果，但扩展到 150 ohm 以上后，高阻段出现随阻值增加而逐渐偏小的问题。

## 现象

### 1. 高阻段随阻值增加逐渐偏小

在补偿前，5 mA 扫描中低阻和 150 ohm 附近尚可，但 160 ohm 以上开始变负，且阻值越高偏差越大。典型数据如下：

| 参考电阻 | 补偿前板载电阻 | 误差 |
| ---: | ---: | ---: |
| 150.0505 ohm | 150.0554 ohm | +4.9 mOhm |
| 160.0565 ohm | 160.0527 ohm | -3.8 mOhm |
| 180.0555 ohm | 180.0332 ohm | -22.3 mOhm |
| 200.0415 ohm | 199.9933 ohm | -48.2 mOhm |
| 210.0420 ohm | 209.9808 ohm | -61.2 mOhm |
| 220.0410 ohm | 219.9643 ohm | -76.7 mOhm |
| 280.0430 ohm | 279.8625 ohm | -180.5 mOhm |
| 360.0420 ohm | 359.6495 ohm | -392.5 mOhm |

误差趋势更接近二次项或等效并联支路，而不是单纯固定增益错误。

### 2. 同一 200 ohm 负载下改变电流，误差没有随电压成比例扩大

对 200.0415 ohm 负载分别使用 2.5 mA、5 mA、7.5 mA、10 mA 测试：

| 设定电流 | 板载电压 | 板载电阻 | 误差 |
| ---: | ---: | ---: | ---: |
| 2.5 mA | 500.245 mV | 200.0027 ohm | -38.8 mOhm |
| 5 mA | 999.937 mV | 199.9929 ohm | -48.6 mOhm |
| 7.5 mA | 1499.674 mV | 199.9895 ohm | -52.0 mOhm |
| 10 mA | 1999.827 mV | 199.9881 ohm | -53.4 mOhm |

如果主因是电压 ADC 随电压升高产生明显非线性，误差应随 0.5 V 到 2.0 V 明显扩大；实际扩大幅度较小。因此主因不是简单的 U14 电压通道满量程非线性。

### 3. `adcf` 采样动作会改变 DMM 看到的负载电压

使用数字万用表同时测负载电压时观察到：

```text
未执行 adcf 时，DMM 约 1.0003 V
执行 adcf 时，DMM 约 0.9996 V
同时 adcf 输出约 1.0000 V
```

也就是说，执行 `adcf` 时负载真实电压会下降约 0.7 mV。以 200 ohm 负载估算：

```text
0.7 mV / 200 ohm = 3.5 uA
```

这说明有约 3.5 uA 的电流没有流过标准电阻，而是被测量支路消耗或旁路掉。固件用 R64 测得的总电流做分母，导致 `R = V / I_total` 偏小。

### 4. R64 电流采样本身正常

在 5 mA 条件下直接测 R64 两端电压约为 5 mV，对应：

```text
5 mV / 1 ohm = 5 mA
```

这与 `adcf` 输出电流一致，说明总电流采样链路没有明显错误。问题不是 R64 或 U12 电流 ADC 把电流读大，而是总电流中有一部分没有流过被测电阻。

## 排查过程

### 步骤 1：排除脚本解析和参考值匹配问题

`tools/plot_mutiR.py` 已支持新的 DAQ6510 参考值列表格式，并按测得电阻与参考档位匹配。复核后，高阻段负偏差存在于原始 `adcf` 输出本身，不是 CSV 或图表脚本引入。

### 步骤 2：排除 `adcf` 滤波暂态

比较每个 `adcf 20` 块的 20 点均值和后 10 点均值，高阻段差异通常小于 1 mOhm，远小于几十到几百 mOhm 的高阻负偏差。因此一阶滤波状态不是主因。

### 步骤 3：排除电流设定或 R64 采样错误

R64 实测 5 mV 对应 5 mA，与固件电流读数一致。若使用 DMM 电压和参考电阻反推实际流过标准电阻的电流，会比 R64 总电流小几 uA。这说明多出来的电流是真实流过板子某个支路，而不是电流 ADC 误读。

### 步骤 4：通过隔离实验定位到 V+/V- 电压采样支路

实验：

1. 保持 `I+ / I-` 接标准电阻，板子输出电流。
2. 断开 `V+ / V-` 到负载的连接。
3. DMM 仍测标准电阻两端电压。
4. 执行 `adcf`。

结果：DMM 电压不再下降。

结论：让负载电压下降的支路来自板子的 `V+ / V-` 电压采样路径，而不是电阻箱、I 路输出、R64 或电源本身。

### 步骤 5：尝试启用 AD7190 输入 buffer，确认不适合作为最终方案

尝试打开 U14 AD7190 输入 buffer 后，DMM 电压下陷现象得到缓解，但板载电压和电阻读数明显被拉低，150.007 ohm 也受影响。

原因判断：

- AD7190 buffer 模式对输入脚绝对电压和共模范围有要求。
- 当前 V- 可能接近 AGND，U14 前端又带有板级 R/C 网络，buffer 模式不满足输入范围条件。
- 因此不能通过简单打开 buffer 解决。

最终决定保留 U14 无 buffer 配置。

## 可能原因

最符合全部现象的原因是：

```text
U14 电压采样支路在 AD7190 无缓冲转换期间表现为动态负载。
该动态负载从 V+/V- 负载两端吸收或旁路几 uA 电流。
R64 测到的是总电流，标准电阻实际电流略小。
固件原来用总电流计算 R = V / I_total，因此高阻段偏小。
```

该问题与 AD7190 手册中对无缓冲输入的描述一致：无缓冲输入会对信号源呈现动态负载，外部 R/C 和源阻抗可能带来增益误差。板上 U14 前端包含继电器 K1、R48/R49、C88/C89、C97 等电压采样网络，这些器件和布线共同决定了等效采样支路负载。

## 最终代码解决方案

### 设计原则

1. 不启用 AD7190 buffer。
2. 不修改原始 `I` 和 `V` 输出，便于继续观察 ADC 原始行为。
3. 只对外部路径电阻计算进行补偿。
4. 内部 R42 自检不参与补偿，避免影响安全自检。
5. 以 150.007 ohm 为锚点，因为当前外部路径增益校准就是围绕该标准电阻完成的。

### 补偿模型

将 U14 电压采样支路近似为一个等效负载：

```text
I_sense = |V_load| / R_sense_load
I_load  = |I_total| - I_sense
R_comp_raw = |V_load| / I_load
```

但如果直接使用该公式，150 ohm 也会被抬高。因此增加 150.007 ohm 锚点，扣掉锚点处的补偿增量：

```text
R_anchor_delta =
  R_anchor / (1 - R_anchor / R_sense_load) - R_anchor

R_comp = |V_load| / (|I_total| - |V_load| / R_sense_load) - R_anchor_delta
```

当前固件参数：

```c
#define CHIP_MEASURE_VOLTAGE_SENSE_LOAD_OHM   330000.0f
#define CHIP_MEASURE_RESISTANCE_ANCHOR_OHM    150.007f
```

实现位置：

- `Core/Src/chip_measure.c`
  - `ChipMeasure_ComputeExternalResistance()`
- `Core/Inc/chip_measure.h`
  - 新增函数声明
- `Core/Src/main.c`
  - `temp`
  - `adcs`
  - `adcf`
- `Core/Src/thermal_control.c`
  - `tc status`
  - 温度控制中的电阻/温度推算

### 补偿后的验证结果

重新测量后，`mutiR.txt` 中 150 ohm 到 200 ohm 的结果：

| 参考电阻 | 补偿后板载电阻 | 误差 |
| ---: | ---: | ---: |
| 150.0505 ohm | 150.0554 ohm | +4.9 mOhm |
| 160.0565 ohm | 160.0607 ohm | +4.2 mOhm |
| 170.0515 ohm | 170.0552 ohm | +3.7 mOhm |
| 180.0555 ohm | 180.0604 ohm | +4.9 mOhm |
| 190.0485 ohm | 190.0522 ohm | +3.7 mOhm |
| 200.0415 ohm | 200.0442 ohm | +2.7 mOhm |

150 ohm 到 200 ohm 段 RMS 误差约 4.1 mOhm。

`mutiR_add.txt` 中补测结果：

| 参考电阻 | 补偿后板载电阻 | 误差 |
| ---: | ---: | ---: |
| 210.0420 ohm | 210.0476 ohm | +5.6 mOhm |
| 220.0410 ohm | 220.0416 ohm | +0.6 mOhm |
| 280.0430 ohm | 280.0319 ohm | -11.1 mOhm |

280 ohm 仍有轻微负偏，但相比补偿前约 -180 mOhm 的误差已经显著改善。当前补偿参数优先保证 150 ohm 到 220 ohm 区间不过补。

## 后续继续提升的可能

### 1. 多点拟合补偿

当前模型只有一个等效负载参数和一个 150 ohm 锚点，适合快速修正主要误差。若后续希望覆盖 150 ohm 到 360 ohm 或更高范围，可以用更多标准电阻做拟合，例如：

- 150 ohm
- 200 ohm
- 220 ohm
- 280 ohm
- 360 ohm

然后使用分段线性、二次项或查表补偿。但这会让补偿更依赖当前板子、线缆和环境，维护成本更高。

### 2. 将补偿参数迁移到 Flash/NVM

当前补偿参数是编译期宏。后续可把参数迁移到 Flash，增加：

- magic
- version
- CRC
- 串口读取命令
- 串口写入/校准命令

这样每块板可以有独立补偿参数，不需要重新编译固件。

### 3. 优化硬件电压采样前端

代码补偿只能修正当前板子的经验误差，不能消除采样支路本身对被测对象的加载。硬件优化方向包括：

- 在 U14 前增加真正高输入阻抗的缓冲器，并保证共模范围满足。
- 减小或重新设计 V+/V- 前端的 R/C 网络。
- 减少差分大电容对无缓冲 AD7190 输入的影响。
- 优化继电器、端子和 PCB 清洁度，降低泄漏。

如果要做产品级高精度高阻测量，硬件优化是根治方案。

### 4. 改善采样调度

`adcf 20` 连续采样会提高 ADC 输入动态负载的占空比，也会阻塞主循环中的控制服务。后续可以考虑：

- GUI 常规显示使用低频 `adcf 1`。
- 将 ADC 采样纳入统一调度，避免长时间阻塞。
- 控制环内部复用最近一次测量，减少重复采样。

这不能替代电阻补偿，但可以降低调试命令对被测回路的扰动。

### 5. 同步更新分析脚本和文档

当前 `mutiR_summary.csv` 可能不是最新原始日志的再生成结果。后续建议：

- 将 `mutiR_add.txt` 纳入 `tools/plot_mutiR.py` 的输入或合并到主日志。
- 每次测完后重新生成 `mutiR_summary.csv` 和 `mutiR_chart.png`。
- 在图表中区分补偿前和补偿后数据。

## 当前结论

高阻段偏小的根因不是电流采样错误，也不是简单的电压 ADC 固定增益问题，而是 U14 电压采样支路在无缓冲 AD7190 转换期间对 V+/V- 形成动态负载，使部分总电流没有流过标准电阻。

已采用固件层经验补偿：

```text
R_sense_load = 330 kOhm
R_anchor = 150.007 ohm
```

该方案在不影响 150 ohm 校准点的前提下，将 150 ohm 到 220 ohm 区间误差压到约数 mOhm 量级，对 280 ohm 也有明显改善。若后续目标是更宽阻值范围或更高绝对精度，应优先考虑硬件前端优化或多点参数化校准。
